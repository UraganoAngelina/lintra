## Schema e oracolo indipendente

Nuovo semantic/v1 schema sintetico 14 byte: NUMBER Numeric Exact 3/range 1..4,
DATE DDMMYYYY Exact 8, CODE AN 3/right-pad space strip/dominio logico A.
Nessuna baseline di tracciato o golden precedente toccata. Le regole sono nello
schema; il produttore non conosce nomi/posizioni dei campi. Record key dichiarata
non implica unicità cross-record LocalOnly (P13 resta aperta).

valid contiene due record ai limiti 1 e 4, data bisestile e anno minimo.
invalid contiene cinque record: uno valido, uno sotto range, uno con data e
codice invalidi, uno con tutti e tre invalidi, uno con NUMBER non numerico.
Attesi: 5 processati/1 valido/4 invalidi/7 errori. Due range, due date, due domini,
un tipo; niente range a cascata dopo 00X. Ogni errore è ordinato per riga/campo.
Actual di CODE conserva B/C più due spazi, non la sola vista logica.

Lo script generate_semantic_goldens.py non invoca Rust, legge solo nuovi input
e schema e scrive solo due nuovi scenari. CASES dichiara le sette tuple di esito;
FIELDS/VIOLATIONS congelano il contratto già pubblico di factory/validator.
encoded produce JSON compatto UTF-8 con LF; error costruisce tutti i membri
nell'ordine contrattuale. main usa conteggi espliciti, Counter per distribuzione
ordinata dei codici e hashlib sugli originali. Le sole condizioni dipendono
presenza errori e scenario, non da esiti letti dal motore. È strumento deliberato
di authoring dell'oracolo, non un aggiornamento automatico durante test/CI.
Primo confronto con runtime passato senza correggere attesi da output Rust.
