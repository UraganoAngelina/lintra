## Spiegazioni del codice

`build.rs` acquisisce esclusivamente provenienza di compilazione. La closure
Git accetta output solo se il processo termina con successo; i path Git HEAD,
index, packed-refs e riferimento simbolico sono dipendenze Cargo del build.
Questo include worktree collegati senza assumere che .git sia una directory.
LINTRA_BUILD_COMMIT è un override tracciato: si accetta solo hash completo
esadecimale di 40 caratteri. In sua assenza si usa Git; senza hash disponibile
si dichiara unavailable, senza inventare provenienza. Il valore diventa una
costante nel binario; non si invoca Git né si legge l'host di build a runtime.
Nessuna nuova dipendenza, formato report, API core o workflow di release.

`args::command` aggiunge --version con package version e commit, e descrive
l'esecuzione effettiva validate. `parse` conserva esattamente request, encoding,
policy e opzioni precedenti. L'encoding resta esplicito, Full non selezionabile.
`cli::run` propaga il mapping degli esiti del servizio senza usare il default
clap 2 per errori di sintassi. Anche un errore di stampa dell'help è tecnico.
Il messaggio tecnico su stderr resta separato dai report di validazione.

`command::Failure` è un confine adapter Box<dyn Error>, non un nuovo errore
engine/application. `FailedRun` conserva errore primario tipizzato e Vec dei
soli errori di cleanup (massimo due), source espone il primario e Display
riporta anche le cause di cleanup. `abort` tenta ogni output, anche se il primo
abort fallisce. Non elimina file definitivi o .part appartenenti ad altri run.
`invalid` crea soltanto errori tecnici di configurazione dell'adapter.

`resolved` usa canonicalize per target esistenti, includendo symlink; un target
nuovo risolve il parent già esistente e aggiunge il filename nativo. Solo
NotFound attiva questo ramo; altri errori I/O si propagano. Nessuna creazione
di directory, conversione lossy o inferenza di bundle in cwd. Il parent .
vale soltanto per percorsi di output relativi esplicitamente scelti dall'utente.
`check_outputs` risolve input e le due root e confronta quattro percorsi:
errors, errors.part, summary, summary.part. Rifiuta uguaglianze, collisioni
con input e destinazioni interne alle root. La memoria è costante (quattro
path), non dipende da input/errori. La garanzia riguarda path risolti al
preflight; modifiche concorrenti esterne ai path restano fuori contratto,
come per AtomicReportFile. Rename non modifica l'inode del vecchio definitivo.

`validate` risolve il bundle completo con il resolver approvato e usa la factory
LocalOnly reale. La root reference è controllata come parte del bundle e
protetta dagli output; non viene presentata come provider disponibile.
Crea i due AtomicReportFile con policy Delete. Se la seconda creazione
fallisce, abortisce esplicitamente il primo preservando la causa iniziale.
La closure di produzione mantiene soltanto JsonlSink con writer preso in
prestito e risultato del servizio: il motore continua a leggere in streaming.
Ogni errore di servizio, flush, serializzazione, log o human output passa al
ramo di abort di entrambi i guard prima della pubblicazione.

L'observer mappa soltanto eventi realmente emessi a quattro messaggi JSON
fissi (run_started, trace_started, trace_completed, run_completed) su stderr.
Non include record, valori, PK o path e non alloca una lista di progress.
Il trait non può restituire errori I/O: un Result memorizza il primo errore,
impedisce ulteriori scritture e viene verificato prima della pubblicazione.
Il ramo wildcard ignora gli altri eventi di progresso senza simularli.
Il token nuovo è indipendente, non cancellato; handler Ctrl+C appartiene a
T-P8-05. Nessuna capability di cancellazione CLI dichiarata in anticipo.

Dopo validate il JSONL viene finalizzato, poi il summary serializzato usando
lo started_at autorevole del servizio. HumanReadableSink produce il summary
sul solo stdout; finish controlla flush e il lock restituito è rilasciato
esplicitamente. Questo rende broken pipe/guasti stdout errori tecnici prima
dei rename. Un primo Clippy ha segnalato il lock restituito non consumato:
corretto con drop(human.finish()?) senza sopprimere lint o ignorare errori.

La pubblicazione usa ReportCompletion da status/truncated del servizio.
CompletedInvalid pubblica report completi e ritorna 2, CompletedValid 0;
Cancelled si mappa a 130 e i guard non pubblicano. Nessun nuovo RunStatus.
Se il primo complete fallisce, abort del secondo; se fallisce il secondo,
l'errore tecnico si propaga. L'atomicità è per file, come ratificato T-P5-06:
non viene promessa transazione di coppia o rollback di un file già rinominato.
Anche il testo stdout descrive l'esito di validazione, non certifica il successo
del rename successivo; exit code e messaggio tecnico indicano quel guasto.

## Test

`tests/cli_validate.rs` usa il binario effettivo Cargo, fixture esclusivamente
sintetica già approvata, directory temporanee indipendenti e path con spazi/à.
Ogni processo ha cwd diversa e rimuove solo le due variabili bundle nel proprio
environment. Non cambia env/cwd del processo di test. Fixture::Drop rimuove
soltanto il suo albero temporaneo. NEXT atomico evita collisioni parallele.

- Run valido CRLF: 0, JSONL vuoto, summary local_only con audit complete e
  dimensione raw 8 byte; nessuna riga finale inventata; vecchi report sostituiti.
- Run invalido e riga vuota: 2, codici E_INVALID_DOMAIN ed E_RECORD_LENGTH,
  due record invalidi, JSONL UTF-8 LF; human output INVALID.
- BOM rifiutato/schema malformato: 1, stdout vuoto, vecchi report intatti,
  parti proprie eliminate; nessuna diagnosi normativa simulata.
- Input/schema selezionato assenti: 1 senza fallback, vecchi report intatti.
- Collisioni output/input/schema/reference e final/part: rifiuto senza
  modificare input o schema, nessun file provvisorio lasciato.
- Parte summary preesistente: seconda creazione fallisce, primo guard abortito,
  parte altrui intatta e vecchio errors intatto.
- --version reale: 0 e stringa versione/commit esatta, stderr vuoto.
- Linux /dev/full su stdout: errore reale del writer human, 1 e vecchi report
  intatti; Windows usa i test sink portabili esistenti per guasti write/flush.
- Unix alias symlink all'input: errore 1, sorgente intatta, nessuna parte creata.

Nessuna baseline o fonte architetturale modificata. Rinvii Full/P11/P13/PERSIST,
T-P2-03/M1 invariati. README documenta esecuzione, output, canali e atomicità.
