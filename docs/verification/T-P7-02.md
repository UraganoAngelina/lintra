CancellationToken possiede Arc<AtomicBool>. Default crea un flag false nuovo;
Clone incrementa il contatore Arc e condivide lo stesso stato. Debug non espone
dati record. cancel esegue store(true): chiamate ripetute sono idempotenti e
non esiste reset. is_cancelled esegue load. Entrambe usano Relaxed perché il
flag comunica soltanto la decisione, senza pubblicare dati aggiuntivi o
costituire una barriera per payload esterni. Accessi concorrenti non causano
data race; la cooperazione resta a checkpoint sicuri tra record/trace/pass,
non interrompe strutture critiche. Nessun runtime async o thread creato dal tipo.

ValidationPhase conserva le quattro fasi DET §82. ProgressEvent conserva i sei
eventi DET §81 e i loro payload ID/count. I tipi sono notifiche owned clonabili
e confrontabili, non scheduler o dichiarazioni che una fase sia stata eseguita.
I count sono cumulativi per trace, nessun record o path nei payload.
ProgressObserver riceve mutabilmente eventi sincroni, senza vincolo GUI/Send o
notifica obbligatoria per record. Il chiamante controlla quando emettere;
il throttling resta all'observer. L'impl per FnMut inoltra l'evento unchanged:
una closure può mantenere stato e adattare eventi senza wrapper aggiuntivi.

Tre test reali verificano: stato iniziale, condivisione cloni, idempotenza e
indipendenza di token nuovi; cancel da thread distinto con channel e join
(senza sleep/busy wait/thread pendenti); trait object che riceve tutti gli
eventi in ordine con un solo aggiornamento da un milione di record, dimostrando
che il contratto non richiede un evento per record. Il thread è solo un test
sincrono con join, nessun processo/servizio in background.
