## Contratto minimo e compatibilità

Aggiunta tecnica, nessuna firma precedente modificata:
`LookupNormalization::{Exact, AsciiUppercase}` con
`apply(self, &[u8]) -> Cow<'_, [u8]>`, e
`PreparedReferenceEvidence::observe_with_normalization(key, value, policy)`.
Il risultato conserva DatasetObservation e la sua evidenza originale; non
aggiunge una conclusione normativa binaria per informazioni degradate.

Non esiste una proprietà normalization nell'authoring approvato. Non aggiungiamo
proprietà JSON, default serde, nuove varianti AST o cambiamenti grammar v1/v2.
L'API tecnica richiede una scelta esplicita del chiamante. In T-P11-05 i
constraint dell'authoring attuale devono preservare il lookup esatto: eventuali
trasformazioni dichiarabili nel JSON richiedono un'estensione authoring
separata prima di essere accettate. Non simuliamo la compilazione di una
proprietà inesistente. Non viene autorizzata alcuna trasformazione normativa
per un campo specifico. Nuove policy oltre ASCII uppercase non sono dedotte
né implementate preventivamente.

## Spiegazione completa del codice

`normalization.rs`: enum pubblico Copy/Eq senza Default: Exact è identità,
AsciiUppercase è una trasformazione byte-oriented e indipendente dall'encoding.
Non effettua trim, casefold Unicode, conversione numerica o rimozione zeri.
`apply` usa un match esaustivo. Exact restituisce Cow::Borrowed, anche per
input vuoto o binario. Uppercase controlla prima la presenza di a..z: se
esiste alloca il solo buffer trasformato tramite to_ascii_uppercase; altrimenti
riusa la slice senza allocazione. Ogni byte fuori a..z resta identico, dunque
larghezza e offset sono preservati e il secondo passaggio è idempotente.
L'input originale e le chiavi del dataset non sono mutati.

`evidence.rs`: il nuovo metodo risolve prima l'evidenza con `?`: dipendenza
non registrata → None esterno. Se il set esiste, normalizza soltanto la query
e consulta contains con una slice; il Cow temporaneo vive fino alla fine
della query. Se manca il set, Option::map non esegue la closure e restituisce
osservazione con None interno, mai false. L'evidenza restituita è lo stesso
riferimento presente nello snapshot: stato, anomalie, identità, digest atteso
e reale e policy di preparazione restano invariati. Degraded+presente non
viene promosso a Verified. Nessun I/O, copia del dataset o materializzazione
Union. La query che richiede uppercase può allocare una volta; non promettiamo
zero allocazioni per input effettivamente trasformato. L'API observe esistente
resta esatta e senza allocazioni.

`mod.rs` registra il modulo privato; `lib.rs` esporta soltanto il tipo pubblico.
Non vengono esposti costruttori compilati né aggiunte dipendenze inverse.

## Test e motivazione

Unavailable rimane None interno; identità non registrata resta None esterno.

non cambiano dati o risultato sulla base del comportamento del provider.
