## Nuovi test e spiegazioni del codice

Quattro test portabili aggiunti a tests/cli_validate.rs:
- Processo senza opzioni restituisce 1 e help su stderr; --help/validate --help
  restituiscono 0 con stdout. Nessun parser test-only o crate di test aggiunto.
- Coppia CLI completa prevale su due variabili environment non valide; il
  comando esegue realmente il servizio e pubblica report completi.
- Coppia environment completa risolve il bundle senza root CLI; un solo
  componente environment fallisce tecnicamente, senza completare la coppia da
  un livello inferiore, mantenendo sentinel e nessuna parte propria.
- Copia reale dell'eseguibile in directory con spazi, bundle adiacente e cwd
  estranea: run valido. Poi environment completo verso directory vuote prevale
  sul bundle adiacente valido: schema assente è errore senza fallback. File
  precedenti preservati. La copia è un test di risoluzione, non una release.

Helper request costruisce solo argv/env del processo figlio, con nessuna root
CLI. I path restano nativi, nessuna modifica globale di cwd/env. Riusa la Fixture
esistente con cleanup esclusivo dell'albero sintetico. EXE_SUFFIX seleziona il
nome copiato Windows/Linux senza assumere estensione. fs::copy conserva i
permessi eseguibili su Unix e copia un binario nativo già disponibile su Windows.

Nuovo tests/cli_windows_signal.rs, compilato/eseguito soltanto su Windows,
collega esclusivamente Kernel32 di sistema, senza aggiungere dipendenze:
- Binding FFI ABI system esatti per API console, documentati con SAFETY. Nessun
  puntatore esterno viene dereferenziato; HANDLE standard sono prestiti OS e
  vengono soltanto ripristinati tramite SetStdHandle, mai chiusi dal test.
- Console::attach riusa console esistente (GetConsoleCP), oppure ne alloca una
  nel solo processo test e ripristina gli handle standard ereditati da Cargo.
  Il guard stacca soltanto la console propria, dopo uscita del figlio. Il test
  è in un binario dedicato con una sola funzione, senza altri test paralleli
  che mutino la console di quel processo.
- Fixture temporanea con copia dello schema sintetico e 1.048.576 record validi
  (7.340.032 byte). L'input è scritto per blocchi limitati, mai caricato dal CLI.
- Il figlio nasce con CREATE_NEW_PROCESS_GROUP e condivide la console sender.
  Dopo l'evento reale run_started, GenerateConsoleCtrlEvent invia CTRL_BREAK_EVENT
  al gruppo nonzero del solo PID figlio. Non invia Ctrl+C broadcast al runner:
  Microsoft documenta che CTRL_C_EVENT non può essere mirato a quel gruppo.
  ctrlc gestisce Ctrl+Break mediante lo stesso callback di cancellazione.
- Stderr resta aperto, evitando BrokenPipe spurio; ChildGuard termina/raccoglie
  un figlio ancora posseduto in caso di panic. Dopo wait_with_output si richiede
  130, CANCELLED/incomplete e vecchi report intatti; nessun .part proprio.
  Non si salta il test se console/evento fallisce: il runner deve dimostrare
  il risultato. Nessuna opzione o env di test nascosta nel binario produttivo.

Fonti primarie Win32 consultate per ABI, costanti e proprietà dei gruppi:
[GenerateConsoleCtrlEvent](https://learn.microsoft.com/en-us/windows/console/generateconsolectrlevent),
[AllocConsole](https://learn.microsoft.com/en-us/windows/console/allocconsole),
[process creation flags](https://learn.microsoft.com/en-us/windows/win32/procthread/process-creation-flags).
La compilazione GNU locale controlla i binding; solo CI Windows può confermare
consegna dell'evento e comportamento runtime, non ancora dichiarati superati.
