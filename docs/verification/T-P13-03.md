## Contratto pubblico

ContextStore conserva le firme DET §71: insert(ProjectedRecord) -> Result;
find(trace,join,key) -> Result<RelatedRecordSet>; iter_trace -> iterator borrowed.
RelatedRecordSet mantiene tutti i risultati; non offre una selezione scalare
arbitraria. find cerca le chiavi Target di 13-02: Source serve al chiamante
per costruire la query, non è un secondo indice di record candidati. Questo
rende corrette anche self-join con tuple source/target differenti.

ContextError appartiene a context, implementa Error, senza import application:
InvalidTraceId/InvalidJoinId/InvalidLineNumber/DuplicatePosition. Quest’ultimo
è doppia posizione dello stesso input trace/riga, non doppia PK normativa;
trace diversi possono avere uguale riga e record con la stessa PK a righe
diverse restano tutti conservati. Il driver non emette ValidationError.
Display è fisso, senza identity o valori sanitari. Debug dell’errore contiene
solo il trace/schema ID e numero riga quando pertinente, mai payload.

RelatedRecordSet possiede soltanto uno slice borrowed di Arc<ProjectedRecord>.
new rende la view costruibile anche dagli altri implementer del port; essi
restano responsabili dell’ordine dichiarato dal trait. len/is_empty leggono
il conteggio senza scansione; iter produce riferimenti immutabili, con
ExactSizeIterator e DoubleEndedIterator, senza copiare record o creare un
Vec a ogni ricerca. La lifetime dei record segue lo store; durante il borrow
Rust impedisce insert mutabili. Debug mostra solo il numero dei match.

## Implementazione — ogni struttura/funzione/condizione

JoinIndex è HashMap<JoinId, HashMap<JoinKey, Vec<Arc<ProjectedRecord>>>>. TraceContext
ha records BTreeMap<u64,Arc<ProjectedRecord>> e targets JoinIndex. La mappa
esterna di InMemoryContextStore seleziona il trace; nessuna iterazione di
HashMap determina l’ordine restituito. new delega a Default, creando uno store
vuoto e indipendente. Debug custom mostra soltanto numeri trace/record.

insert valida prima di qualsiasi mutazione: trace ID non vuoto; riga >0;
tutti gli ID join presenti nel record non vuoti; nessuna posizione uguale già
in records del trace. Questi sono gli unici Err recuperabili; in ogni caso
records e indici preesistenti restano identici, nessuna sostituzione del primo
record. Nessuna normalizzazione/trim degli identificativi o delle chiavi.

Dopo la validazione Arc::new prende ownership della proiezione una volta.
Lo store crea il TraceContext se assente. Per ciascun binding, soltanto
Side::Target + Value::Available viene indicizzato; Source e MissingComponent
restano nel payload ma non diventano falsi candidati. La join e la chiave
selezionano il bucket; la chiave viene clonata per la mappa, non ricostruita
con stringhe o separatori ambigui. partition_point sul numero riga calcola
il punto d’inserimento: input già ordinato appende, inserimenti fuori ordine
mantengono ugualmente ordine crescente. Nessuna deduplicazione del bucket
per uguaglianza dei byte/PK e nessun first() a occultare match multipli.

Arc::clone aggiunge un puntatore allo stesso payload per ciascun bucket;
records conserva lo stesso Arc. values/identity non sono clonati per indice.
Nessuna copia di RecordView o riga fisica; si conserva solo ProjectedRecord
prodotto dal projector. Le allocazioni standard possono abortire su OOM come
le altre collezioni Rust; non viene promessa una transazione recuperabile su
OOM. Tutti i Result::Err effettivamente restituiti precedono le mutazioni.

find controlla gli ID trace/join non vuoti, poi effettua tre lookup borrowed
trace → join → key e restituisce lo slice del bucket o uno slice vuoto.
Non alloca un elenco dei match, non normalizza la chiave, non consulta file o
schema nel ciclo. Trace/join non presenti nello store sono zero match, non
un input esplicitamente disponibile. Nessun errore normativo automatico.
iter_trace prende i values BTreeMap in ordine di riga e dereferenzia gli Arc;
trace assente → iterator vuoto. Il Box è quello del contratto del port, non
materializza un Vec di record per la scansione. Nessun accesso mutabile al
payload restituito, così i binding non possono divergere dagli indici.

## Test e motivazioni

Cinque integration test, schema sintetico realmente compilato e proiezioni
project_record reali. schema deriva i tre campi 2 byte da una fixture tecnica,
crea tre trace e join S→T/SELF/OTHER con policy esplicite; nessuna baseline
modificata. projected usa il vero schema del trace; key usa build_join_key;
lines consulta ogni risultato senza selezione scalare implicita.

1. Trait object Box<dyn ContextStore> realmente eseguito: zero, uno, tre match;
   inserimenti 3/1/2 restituiscono 1/2/3, iterator inverso 3/2/1, PK uguali
   restano tre record. Ordine indipendente da inserimento e hash seed/OS.
2. Isolamento trace/JoinId/byte key, source non indicizzato, self-join cerca
   Target e non Source; trace senza join rimane iterabile, query assente zero.
3. Componente target missing: S_T non trova una chiave di spazi inventata,
   OTHER trova ancora il record dalla PK; stato MissingComponent conservato.
4. Doppia posizione con payload diverso rifiutata, poi riga zero/trace vuoto/
   join vuoto rifiutati; il record originale e tutti gli indici rimangono
   invariati. Query con ID vuoti hanno errore tecnico esplicito.
5. Puntatori di iter_trace e di due lookup sono identici: una sola proiezione
   owned condivisa, byte NUL/0xff preservati. Debug store/set non contiene
   l’identity sintetica; una seconda istanza nasce vuota, nessuna storia globale.

Esecuzione mirata: 5 passati, zero falliti. Gate completi in corso. Nessun
placeholder di persistenza/cardinalità, nessun wrapper che ignori un parametro.
