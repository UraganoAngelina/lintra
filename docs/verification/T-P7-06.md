## File e spiegazione dettagliata del codice

- tests/integration.rs registra esplicitamente il modulo sotto integration/:
  Cargo scopre i file test nella root, non ogni file dentro sottodirectory.
- tests/integration/synthetic_service.rs esercita il servizio applicativo reale.
- tests/fixtures/application/schema.json dichiara esclusivamente regole di prova,
  non normative: sei byte, due campi required, numeric con zero stripping a sinistra
  e dominio logical 1, AN con spazio stripping a destra e dominio A/É. Missing
  è spaces, non il default globale zeri. Identità tecnica su F2, PK su F1.
- AGENTS.md e IMPLEMENTATION_STATUS.md registrano mandato, task ed evidenze.

Fixture possiede una directory unica (PID, timestamp, contatore atomico), root
repository e input. `new` scrive flow.json nella struttura reale flow/version e
solo byte sintetici. `request` dichiara Trace/LocalOnly e opzioni esplicite;
`service` usa filesystem repository/registry/compiler reali e inietta solo il
clock. Drop elimina solo la directory posseduta, quando gli handle sono chiusi.
Nessun test modifica cwd, home, ambiente o file di altri scenari.

FixedClock restituisce UNIX_EPOCH tramite il trait vero: non modifica un esito
postumo. Reports possiede JsonlSink e byte summary. `new` inizializza i writer;
`on_error` delega alla serializzazione di produzione; `on_summary` prima invia
il callback al JSONL per flush, poi serializza il summary autorevole. Ogni `?`
conserva il fallimento tecnico. Vec di report solo per piccole fixture test;
non è un accumulo globale di errori nell’engine.

Il test valido usa CRLF, spazi di padding e ultima riga senza terminatore.
La É è multibyte: la larghezza rimane tre byte sul campo AN. Tre record validi,
JSONL vuoto, summary LocalOnly/VALID e audit completo di 22 byte provano lettura
e stage reali, senza trim del record. Timestamp proviene dal clock iniettato.

Il test invalido esegue due volte la vera applicazione su sette righe. Copre
ordine per riga/campo/stage: tipo numeric, dominio numeric, dominio AN, due
required nella stessa riga e due lunghezze errate. Sette errori su sei record
invalidi: i contatori non devono equiparare errori e record. I record malformati
emettono solo length, senza identity/field pipeline. Il JSONL viene decodificato
solo per asserire codici/righe/ID, ma il confronto deterministico è sui byte
originali di entrambe le esecuzioni, senza parsing/riordino/normalizzazione.
Il ramo `if let Some(previous)` confronta dal secondo run, perché il primo
stabilisce il termine di confronto; non aggiorna mai golden. CR e BOM sono vietati
nell’output; i report summary reali mantengono il loro elapsed, non mascherato.

Il test schema gap sposta F2 alla posizione 5 mantenendo length 3 su record 6:
il compiler deve rifiutare il piano invalido. Elimina anche l’input: il risultato
deve essere SchemaCompilation prima dell’apertura, non Input e non invalidità
normativa. Report vuoti ed eventi assenti dimostrano il fallimento prima del run.
