## API minime e compatibilità

EvaluationContext e FieldValueResolver restano invariati: il nuovo
ProjectedEvaluationContext implementa la porta già ratificata, senza aggiungere
campi obbligatori ai literal di tutti i consumer locali. UnknownReason contiene
già i tre motivi richiesti, riutilizzati senza duplicare enum o verità logica.
RawRef/RawRefLocal/RawRefExternal ora nominabili dal re-export; nuovo helper
resolve_field_reference sul compiled flow, senza nuovi constructor di schema.

CrossRecordInputs dichiara i trace effettivamente disponibili e i parametri
runtime. JoinParameterValue Text conserva spelling/zeri; Integer usa il tipo
esatto già esistente, nessun float. Il costruttore usa e verifica entrambi,
non ignora un parametro per soddisfare una firma futura. Questi sono contratti
pure del contesto, non modifiche anticipate a ValidationRequest/CLI/service.
Un unico store per run e namespace preflightato rimane requisito del chiamante:
non dichiarata verifica multi-tenant del payload senza metadati di provenienza.

RelatedLookup conserva una ref alla CompiledJoinSpec e RelatedResolution:
Records(set) oppure Unavailable(reason). La join mantiene JoinId, cardinalità,
policy e messaggi. Set vuoto con input disponibile non viene confuso col trace
indisponibile. NotApplicable non viene convertito in Satisfied: il resolver
scalare restituisce indisponibilità del valore e il futuro evaluator applica
l’esito distinto dalla policy conservata. Nessun risultato normativo emesso qui.

Riduzioni consensus e primitive set appartengono all’integrazione seguente:
helper scalare rifiuta cardinalità set e ogni reduction; context rifiuta
reduction prima di qualunque lookup. Accesso scalare diretto incoerente su set
è UnsupportedPlan. Non si appiattiscono tuple, si sceglie first() o si maschera
il requisito con RelatedRecordMissing. Il lexer/authoring è invariato.

## Binding — ogni funzione e condizione

FieldReferenceError distingue source/target trace assente, campo/join assente,
join di altro source/target, cardinalità non scalare e reduction non supportata.
Display fisso senza contenuto sorgente, Error senza falsa causa interna.
resolve_field_reference trova il source con posizione checked nella lista
immutabile del flow. Local risolve field ID in field_index del trace. External
risolve JoinId globale, verifica source, risolve target richiesto e verifica
che coincida con target della join. Richiede assenza di reduction e cardinalità
ZeroOrOne/ExactlyOne prima di produrre il riferimento scalare. Infine risolve
campo target e conserva tutti gli indici/ID reali nella variante External.
Nessun lookup per nome normativo, latest, normalizzazione o binding inventato.

Il vecchio resolve_local_ref e compile_local_expr non cambiano: il compiler
pubblico resta chiuso per il percorso cross non ancora orchestrato. Il nuovo
helper legge solo un CompiledFlowSchema già verificato; non rende forgiabile
un flow né inserisce regole arbitrarie in uno schema esistente.

## Contesto — ogni struttura/funzione/condizione

JoinParameterValue è typed Text/Integer, Clone/Eq, Debug redatto mostra solo
la variante. CrossRecordInputs è un bundle borrowed senza default impliciti.
RelatedContextError distingue source trace/posizione, trace input non dichiarato/
duplicato/source assente, parametro invalido/mancante, binding incoerente,
reduction non consegnata e Store(ContextError). Display fisso e source preserva
il vero errore dello store: un fallimento tecnico non diventa assenza normativa.

ProjectedEvaluationContext contiene flow/source borrowed, source_index verificato
e una mappa ordinata di RelatedLookup borrowed per join index. Nessun buffer
input copiato o filesystem. new:
1. Risolve source trace e richiede riga >0.
2. Ogni available trace deve esistere e comparire una sola volta; anche il source
   deve essere dichiarato disponibile, non dedotto dai record già nello store.
3. Verifica tutti i parametri forniti contro le definizioni: stringa identica
   a una voce allowed_values, intero nel range inclusivo e tipo corrispondente.
   Parametri sconosciuti, di tipo errato o fuori dominio rifiutati, inclusi
   quelli forniti ma non usati da questa join. Nessun valore scelto come default.
4. Preflight completo delle join source prima della prima query: reduction non
   ancora integrata rifiutata; ogni indice namespace deve esistere e avere un
   valore runtime validato; binding Source effettivo deve essere nel projected.
5. Solo dopo prepara i related: target input indisponibile -> TraceInputUnavailable,
   senza interrogare lo store; source key MissingComponent -> FieldUnavailable,
   senza inventare chiave; key Available -> find sul vero target/JoinId.
   Ogni errore find è Err(Store), non set vuoto. La snapshot è poi immutabile
   durante la valutazione delle espressioni.

related(index) espone borrowed lo stato e la join, consentendo al futuro rule
executor di preservare policy/NotApplicable e diagnostica. Non nasconde una
mancanza sotto un booleano. Il contesto non trasforma un record assente in
False anche per IsPresent/IsMissing: restituisce Unavailable con causa.

resolve_value gestisce Local sul source projected, External sulla join preparata.
External verifica che join index/ID e target trace index del piano coincidano;
incoerenza -> UnsupportedPlan. Rifiuta scalari su cardinalità set. Propaga lo
stato Unavailable; set disponibile vuoto -> RelatedRecordMissing; len diverso
da uno -> AmbiguousJoin. Solo dopo il controllo len==1 legge l’unico elemento:
non è una scelta arbitraria del primo di una relazione multipla. Verifica anche
che il record restituito appartenga al trace target. Campo/indice/ID passano
poi alla stessa funzione projected_value di accesso raw/logical.

projected_value controlla indice campo e ID, presenza del valore nella projection
e larghezza esatta della slice fisica. Campo non proiettato o incoerente resta
FieldUnavailable, non un valore vuoto o illeggibile certificato. MissingValuePolicy
agisce sui raw prima delle trasformazioni; raw_target restituisce gli stessi
byte, logical applica soltanto alignment dichiarato tramite logical_value.
Errore di piano -> UnsupportedPlan. Non fa trim generale, uppercase, conversione
numerica, UTF-8 lossiva o copia della riga.

FieldValueResolver delega resolve_field/raw a questi accessi; resolve_derived
legge il vero piano derived del source e usa DerivedValueEvaluator con lo stesso
resolver. Indice non dichiarato -> FieldUnavailable, nessuna data/zero simulati.
Nessun import application/CLI, nessun costruttore di ValidationRunError o sink.

## Test

projector/InMemoryContextStore; tre trace sintetici, chiave composta KEY/PK,
field identity per rendere esplicita la projection VALUE/TEXT, padding dichiarato,
substring reale. Parametri org=001 e year=2026 espliciti, namespace obbligatorio.
Nessun dato paziente o file normativo nuovo.

1. Related scalare reale 07 vs source 05; logical Cd vs raw Cd-space-space,
   local Ab e derived substring Ab. Campo realmente missing su un target
   presente resta Missing, distinto da relazione assente.
2. Zero/troppi match/trace indisponibile: motivi RelatedRecordMissing,
   AmbiguousJoin, TraceInputUnavailable. IsPresent e IsMissing mantengono Unknown;
   NOT preserva il motivo; AND/OR rispettano le tavole, anche con operand order
   invertito. Policy NotApplicable e JoinId conservati, mai Satisfied fittizio.
3. Parametri spelling diverso, tipo errato, range violato, nome sconosciuto,
   valori mancanti e trace input duplicato/ignoto/source assente rifiutati prima
   di qualunque lookup. CountingStore delega a store reale e inietta una failure
   per verificare la causa tecnica preservata, non simula feature assenti.
4. Source key missing: Unknown FieldUnavailable e zero chiamate allo store.
5. Binding pubblico verifica ogni mismatch source/target/join/field e rifiuta
   scalare su ZeroOrMany, senza prendere una riga arbitraria.
6. Self-join reale; riferimenti diretti con join ID/field index incoerenti non
   accedono a dati arbitrari; projected privo del binding richiesto rifiutato.
7. Reduction consensus presente -> errore esplicito prima del lookup, sia
   context sia helper, mai un negativo normativo da feature non implementata.
