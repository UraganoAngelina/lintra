## evidence.rs — modello di sola lettura

DatasetAvailability è Verified/Degraded/Unavailable; PreparationPolicy è
Strict/ContinueWithAvailableEvidence. DatasetIoOperation distingue risoluzione
root, ispezione path, risoluzione path e lettura file. MembershipProperty nomina
i quattro campi obbligatori; MembershipFormatIssue distingue BOM, JSON invalido,
proprietà duplicate/ignote/mancanti/invalide, versione incompatibile, hex e
entry duplicate con indice. Nessuna classificazione basata sul parsing di
messaggi umani di errore.

DatasetAnomaly separa il tipo di file non utilizzabile, I/O con vero Arc<io::Error>, IntegrityMismatch, identità
invalida/diversa e formato con eventuale vera causa serde_json. source() espone
solo la causa realmente presente; un hash diverso non fabbrica un errore JSON
o una causa I/O. Le anomalie sono memorizzate per dipendenza, non emesse per ogni
record. Non sono ValidationError e non hanno effetto sui contatori normativi.

DatasetEvidence ha campi non costruibili/modificabili dal chiamante: richiesta,
hash atteso, hash effettivo opzionale, identità dichiarata opzionale, stato,
policy e lista di anomalie. Getter in borrow, stati/policy Copy. L'assenza del
digest indica che non sono stati ottenuti tutti i byte originali, mai digest
atteso spacciato per calcolato. Identità ambigua/non decodificata resta None.

PreparedReferenceEvidence possiede HashMap<DatasetKey,Arc<dyn LookupSet>>, un
vettore ordinato di evidenze e indice HashMap key→posizione. Nessun provider,
root o handle file viene conservato nel contesto di lookup. datasets() mantiene
l'ordine dichiarato includendo gli indisponibili; evidence(key) usa get checked.
observe usa soltanto lookup HashMap/HashSet e ritorna DatasetObservation in
borrow: osservazione Some(true/false) se esiste un set, None se indisponibile.
Una dipendenza non registrata ritorna invece None esterno, senza inventare
un dataset richiesto. availability/evidence accompagnano sempre la misura.
Non è un esito di conformità normativa: Degraded+true sarà ProvisionalPresent
nella futura integrazione, non un VerifiedPresent anticipato.
Nessun accesso al raw LookupSet degradato viene esportato dallo snapshot.

## membership_format.rs — decodifica rigorosa

Root implementa DeserializeSeed/Visitor su un oggetto, non serde_json::Value
con comportamento last-wins. visit_map tiene i nomi già letti e rifiuta un
duplicato prima di leggere il secondo valore; anche un nome JSON con escape
che decodifica allo stesso nome viene rilevato. Ammette solo quattro proprietà,
usa i tipi esatti (u32/String/String/Vec<String>) e richiede tutte le proprietà.
Il contesto registra la categoria tipizzata mentre serde conserva la causa.

parse usa il Deserializer originale e end() per vietare un secondo documento
o una coda non whitespace. Errori sintattici/EOF diventano InvalidJson;
errori strutturali conservano la categoria specifica e l'errore originale.
Non corregge JSON, non elimina BOM, non raccoglie voci prima di un fallimento.

decode_keys lavora sulle stringhe già decodificate dal JSON. as_chunks::<2>
fornisce coppie [u8;2] e remainder; resto non vuoto è InvalidHex. nibble ammette
solo 0..9/a..f, non uppercase/spazi/segni/Unicode. Ogni coppia produce un byte,
anche 00/ff; stringa vuota produce Vec vuoto esplicito. HashSet::insert distingue
entry nuova da duplicata; un duplicato fa fallire TUTTO il dataset, senza
promuovere il sottoinsieme letto a sorgente completa. Nessun recupero selettivo
è autorizzato qui: formato invalido → Unavailable, senza membership recuperata.

## filesystem.rs — configurazione e confine di accesso

FileSystemReferenceDataProvider contiene root PathBuf, dipendenze esplicite e
indice per chiave. new rifiuta root vuota, key invalida, metadata_attributes
non vuoti, path non portabile/relativo e coppia duplicata. Lo fa prima delle
letture dataset; i metadata non supportati sono errore fatale di binding,
non assenza da tollerare. Le root native relative sono legate una volta alla
cwd con errore I/O originale se la cwd non è risolvibile. Nessun file manifest,
scansione o nome/versione dedotto. ReferenceDependency è il modello esistente,
re-esportato come metadata; non apre constructor compiled.

portable_relative considera solo componenti separati da slash: rifiuta
componenti vuoti, . / .., backslash/colon/control e caratteri non portabili,
spazi/dot finali e nomi dispositivo Windows (anche varianti con estensione).
È una policy tecnica di path, mai un alfabeto normativo per codici o ID.

checked_path parte dalla root canonica, ispeziona ogni componente con
symlink_metadata, rifiuta symlink, intermedi non directory e destinazione non
regolare senza aprirli: tipo non utilizzabile → Unavailable. Canonicalizza il risultato e ne verifica il prefisso per componenti
rispetto alla root canonica prima di leggere. Errori I/O diventano indisponibilità
tipizzata; violazioni del confine restano Error anche in Continue.
Una root esistente non directory produce la vera causa I/O di percorso
non risolvibile, senza essere aperta come dataset. Una root mancante/non
risolvibile produce evidenza Unavailable per ogni dipendenza in
Continue, permettendo la futura prosecuzione dei controlli indipendenti.

**Limite esplicito:** questi controlli sono su percorsi in una configurazione
stabile. Non sono risoluzione atomica openat/capability né protezione TOCTOU
contro sostituzioni ostili concorrenti dell'albero. Root/albero devono essere
sotto controllo del deployment. Non viene dichiarata una garanzia inesistente.
Un root symlink esplicitamente selezionato viene risolto come root canonica;
i symlink dei path dei dataset sotto quella root sono rifiutati.

## Preparazione e stati

prepare_selected crea mappe/vettore locali, piano vuoto senza letture. Risolve
la root una volta per snapshot; per ogni dipendenza nell'ordine esegue load_one.
Continue conserva evidenza di tutte le dipendenze e inserisce solo set utilizzabili;
Strict fallisce sulla prima evidenza non Verified senza restituire snapshot
parziale. Errori di sicurezza scartano lo snapshot in entrambi i casi.

load_one inizializza richiesta/hash atteso e registra distintamente la fase
I/O che fallisce. Dopo una lettura completa calcola SEMPRE SHA-256 originale
prima del parsing, anche per BOM/malformazione/identità estranea. Un mismatch
aggiunge IntegrityMismatch ma non impedisce il parser rigoroso. BOM o errore
JSON aggiungono la rispettiva anomalia e danno Unavailable, con digest reale.
Header decodificato in modo univoco conserva la key dichiarata; versione tecnica
non 1, identità invalida o diversa rendono Unavailable e impediscono il lookup.

Solo dopo header conforme e chiavi hex tutte valide/uniche si costruisce il set.
Zero anomalie → Verified; altrimenti l'unica anomalia possibile in quel percorso
è IntegrityMismatch → Degraded. Hash mismatch + JSON malformato mantiene entrambe
le anomalie e Unavailable, mai un set parzialmente inventato. Nessun rehash di
JSON normalizzato o sostituzione dell'atteso con il contenuto effettivo.

load del trait legacy seleziona solo la dipendenza richiesta e usa Strict;
restituisce Arc solo se Verified, oppure ReferenceDataError::Provider con la
vera FilesystemReferenceError come source. Key non registrata è Unavailable;
un'incoerenza interna dello snapshot è InvalidPreparedState, non un set fittizio.
FilesystemReferenceError distingue configurazione, confine e StrictPreparation
con Box<DatasetEvidence>; Display fisso senza path assoluti o byte paziente.
source() inoltra le vere cause I/O/JSON quando presenti, non crea eccezioni fittizie.

ByteLookupSet è trasferito dall'implementazione in-memory al modulo dataset
come struttura interna condivisa: stesso HashSet<Vec<u8>>, getter e contains
borrowed. InMemoryReferenceDataProvider riusa il costruttore interno e conserva
comportamento e API (incluse entry duplicate coalescenti nel suo registro
esplicitamente fornito). Il filesystem richiede invece unicità del file v1.
Le mappe restano private, immutabili dopo la preparazione; nessun dato normativo
hardcoded, nuovo crate, unsafe o dipendenza inversa di engine/domain.
