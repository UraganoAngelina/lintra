## Codice, condizioni e correttezza

CanonicalSchemaError avvolge la causa serde_json reale: Display fisso,
Error::source preservato. Non è un errore normativo né sostituisce il linter.
ordered distingue object/array/scalar: gli object passano per BTreeMap con
chiavi ordinate lessicograficamente in UTF-8; anche ogni valore annidato è
ordinato. L'array visita ricorsivamente gli elementi **senza riordinarli**;
gli scalari sono mantenuti, senza parsing float, trim, normalizzazione Unicode
o rimozione di zeri da stringhe. L'ordinamento è esplicito anche se il backend
JSON in futuro usasse una mappa con ordine d'inserimento.

canonical_schema_bytes serializza il RawFlowSchema tipizzato in Value,
applica ordered e produce JSON compatto UTF-8 senza BOM/newline finale.
La canonicalizzazione riguarda il modello normativo: default/omissioni sono
quelli già dichiarati dal serializer raw. Il binding encoding.resolved resta
un'opzione runtime non serializzata secondo il contratto esistente, non viene
aggiunto al JSON normativo. Non si pretende equivalenza matematica fra ogni
spelling numerico, normalizzazione di Unicode o conformità RFC 8785.
La forma concreta è fissata dalle fixture; un suo cambiamento futuro richiederà
compatibilità/regressioni, non un cambio silenzioso dell'audit.

schema_fingerprint calcola SHA-256 sui byte canonici effettivi e restituisce
Sha256Digest esistente (formatter hex minuscolo). Riusata sha2 0.11.1 già
approvata, nessuna dipendenza/lockfile nuova. Non è il digest dei byte file JSON
originari né degli input sanitari: whitespace/ordine object non lo cambiano;
contenuto e ordine degli array sì. L'hash non rende uno schema eseguibile.

SchemaRegistry::resolve_with_hash esegue **un solo** load_raw, verifica la
stessa key integrity già esistente, calcola il fingerprint, applica il binding
runtime esplicito e compila. Restituisce ResolvedSchema con schema Arc e hash
privati e getter in sola lettura: il chiamante non può sostituire uno dei due
componenti o rileggerli da un file cambiato. resolve conserva la firma pubblica
precedente delegando e restituendo lo schema; niente cache o lookup latest.
SchemaResolutionError aggiunge Canonical con causa originale; è già non_exhaustive.
Le varianti Load/Compilation e i loro significati rimangono invariati.

## Test e oracolo indipendente

Cinque integration: byte canonici e digest vs oracolo indipendente; parsing
di JSON con chiavi invertite a ogni livello e whitespace diverso; hash cambiato
per metadata/ordine array ma non per binding runtime; round-trip esatto di
numeri da 50 cifre e testo con spazi/zeri/Unicode; registry reale con hash e
compiled della stessa key, più compatibilità del resolve esistente.
raw carica il fixture sintetico; reversed genera testo JSON realmente invertito
(preservando array), senza limitarsi a una mappa già ordinata. Nessun dato reale.

Fixture canonical-schema.json prodotta con Python json.dumps(sort_keys=True,
separators=(',',':'),ensure_ascii=False) dal JSON sintetico preesistente;
canonical-schema.sha256 con hashlib.sha256 su quegli stessi byte. Il Rust
viene confrontato byte per byte, non usato per riscrivere il golden atteso.
Verifica indipendente anche con sha256sum eseguita. Un errore iniziale nel test
usava il costruttore repository con un argomento; corretto usando new+insert
esistenti e rieseguiti i test. Nessuna allow/ignore/baseline normativa modificata.
