## Controlli e ordine

- Formato numerico 1; flow/version/trace/field ID non vuoti, senza spazi
  esterni, case e Unicode preservati; flow non vuoto, trace e field ID unici
  nei rispettivi scope. Nessuna correzione implicita degli identificatori.
- start > 0, length > 0; aritmetica checked sul target usize; endpoint di
  fonte calcolato anche in u64, evitando overflow u32 e false coperture.
- Ordine dichiarativo, gap iniziali/interni, overlap anche annidati,
  record_length positivo con copertura finale esatta e record non vuoto.
  Un filler deve essere un campo esplicito, non spazio inferito.
- Date DDMMYYYY esattamente otto byte; byte set non vuoti/unici e classe
  lowercase sottoinsieme dei byte ammessi. Tipo, formato data e parametri
  enum sconosciuti sono già rifiutati dalla deserializzazione raw chiusa.
  Gli alias legacy sono materia dell’importer, non fallback nel lint.

Le coordinate restano one-based inclusive: nessun ByteRange runtime è
prodotto e la conversione definitiva rimane al compiler T-P3-05. La copertura
usa una vista ordinata per start/indice; non riordina i campi originali.
Il massimo endpoint dell’intera unione rileva anche overlap annidati e
permette di diagnosticare l’ordine invertito senza inventare gap.
Le issue sono aggregate: flow, trace nell’ordine dichiarato, identità trace,
campi nell’ordine dichiarato, mismatch del record alla fine. Dentro il campo:
ID, parametri tipo, posizione/lunghezza, ordine/overflow, gap/overlap.
Gli HashSet servono solo a membership/unicità, mai all’ordine delle issue.

Il lint vuoto certifica solo questi controlli. Riferimenti locali/esterni,
join, PK/identità, regole/presence, regex, compatibilità constraint/tipo,
dataset, binding encoding e capability eseguibili devono essere controllati
dalle task compiler e successive (P9/P10/P13/PERSIST), senza no-op impliciti.
Non si implementano compiler, CLI schema lint, storage, evaluator o CAD.
Nessuna modifica a baseline, contratti sorgente, grammatica o dipendenze.

Raw start/length sono u32: un vero overflow usize non è rappresentabile da
questi due valori sui target x86_64. Il test unitario esercita il medesimo
helper checked con usize::MAX + 1 e verifica il codice RangeOverflow; quello
pubblico usa u32::MAX per entrambi e verifica Gap/RecordLengthMismatch senza
wrap. La diramazione overflow raw su 32 bit è condizionale e non viene
spacciata per eseguita sui runner 64 bit.

Altri test coprono schema valido, filler esplicito, raw invariato, severity,
contesto trace/field, ripetizione deterministica delle issue su trace Z/A,
tipi/alias sconosciuti e formati data rifiutati dal parser.
