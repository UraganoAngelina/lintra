## Implementazione e decisioni

Il workflow esegue una matrice di due job nativi: `ubuntu-24.04` con
`x86_64-unknown-linux-gnu` e `windows-2025` con
`x86_64-pc-windows-msvc`. Si attiva su push a `main`, pull request e
`workflow_dispatch`. I push ai branch di lavoro non aggiungono una seconda
run alle PR. Il gruppo di concorrenza cancella le run superate della stessa
PR/ref; ogni job ha timeout di 20 minuti. `fail-fast: false` conserva le
evidenze di entrambi i sistemi anche se uno dei due fallisce.

`rustup show active-toolchain` usa il file `rust-toolchain.toml`, senza
duplicare il numero di versione nel workflow; `rustup target add` esplicita
il target nativo della riga di matrice. Il pin include anche la libreria
standard GNU per sviluppo locale: il suo eventuale download tramite rustup
non installa MinGW/Wine e non seleziona quel target per i job. Non ci sono
comandi MinGW/Wine o dipendenze da una shell Unix sul runner Windows.

Entrambi i runner eseguono fmt su tutti i file, clippy su tutti i target
Cargo con warning negati, test e build release. I comandi che risolvono il
lockfile usano `--locked`; clippy/test/build ricevono `--target` esplicito.
Solo la riga Windows imposta `-C target-feature=+crt-static`, tramite
`CARGO_TARGET_X86_64_PC_WINDOWS_MSVC_RUSTFLAGS`; Linux ha valore vuoto e
il flag è comunque circoscritto al target MSVC.

L'unica action è `actions/checkout`, fissata al commit completo
`3d3c42e5aac5ba805825da76410c181273ba90b1` di v7.0.1.
Permesso del token: soltanto `contents: read`; credenziali checkout non
persistite. Nessuna pubblicazione, upload o pipeline di release aggiunta.
Il runner Ubuntu scelto per la verifica non risolve la decisione ancora
aperta sulla baseline Linux per la distribuzione finale.

I due test usano soltanto la standard library: una directory temporanea
con spazi viene creata in esclusiva con PID, timestamp e contatore atomico;
una collisione `AlreadyExists` viene ritentata senza riusare directory
esistenti. La guardia RAII rimuove la directory ricorsivamente anche durante
un unwind; nel distruttore la rimozione è best effort. I file sono chiusi
dalle API `fs::write`/`fs::read` prima del cleanup.

Il caso positivo scrive e rilegge byte sintetici invariati per LF, CRLF,
BOM UTF-8 con CRLF e spazi finali, compresa una riga senza newline finale,
in directory e nomi file contenenti spazi. Il caso negativo verifica
`io::ErrorKind::NotFound` su file mancante. I path sono costruiti con
`PathBuf::join`, senza cambiare la working directory globale dei test.

Non sono test di normalizzazione, `BomPolicy`, risoluzione bundle o altre
API di dominio future. Non è dichiarato un ciclo TDD RED: questa task
aggiunge configurazione CI e sonde della I/O già esistente nella standard
library, senza una funzione di produzione mancante da implementare.
